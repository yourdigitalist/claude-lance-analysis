Lance - Technical Architecture Documentation
Overview
Lance is a business management SaaS application for freelancers and small teams, providing client/project management, time tracking, invoicing, client review requests, and subscription billing with a comprehensive admin system.
Tech Stack
Frontend
React 18 + TypeScript (non-strict mode)
Vite 7 (SWC) for bundling
React Router v6 (client-side routing, SPA)
TanStack React Query v5 (selective use for branding/icons/landing)
Tailwind CSS 3 + shadcn/ui components (Radix UI primitives)
React Hook Form + Zod validation
Framer Motion for animations
@dnd-kit for Kanban boards
Recharts for data visualization
Backend & Infrastructure
Supabase: PostgreSQL database, Auth, Storage, Edge Functions (Deno)
Stripe: Subscription billing, checkout, customer portal
Resend: Transactional email
Crisp: Customer chat widget
Deployment
Vercel (static SPA hosting with rewrites)
Dev server: localhost:5173
Architecture Patterns
Authentication & Authorization
Supabase Auth with email/password + magic links
Session storage in localStorage
Three-tier access control:
ProtectedRoute - requires authentication
OnboardingRoute - gates incomplete onboarding
Subscription gate - redirects to /settings/subscription if no active plan/trial
Admin gate - profiles.is_admin flag checked in AdminLayout
State Management
Local React state for most UI
Supabase client for data fetching (mostly useEffect patterns)
React Query for: branding, landing content, icon customizations
TimerContext with localStorage persistence for time tracking
IconSlotContext for customizable icon system
AuthProvider wraps entire app
Data Flow
User authenticates → Supabase session
ProtectedRoute checks profile (onboarding + subscription status)
Pages fetch data via supabase.from().select()
Mutations write directly to Supabase
Edge Functions handle sensitive operations (Stripe, emails)
React Query invalidates cached branding/content

Recent Feature Additions (Services, Proposals, Proposal Settings)
Services Module
Protected routes: /services
Database: public.services with price, currency, recurrence, default_tasks JSONB, and owner-based RLS.
UI: Services list + ServiceFormModal (RHF + Zod), create/edit/delete, recurring period support.
Integration-ready model for future links to proposals/contracts/invoices via service snapshots.
Proposals Module
Protected routes: /proposals, /proposals/:id
Public route: /proposal/:token (token-based client view)
Database: public.proposals + public.proposal_services with owner RLS, identifier sequence trigger, public_token, status lifecycle (draft/sent/read/accepted/archived).
Edge Functions: view-proposal, accept-proposal, send-proposal (email delivery and status transitions).
Storage: proposal-images bucket for cover uploads with signed URL rendering.
Editor architecture: autosave on tab change, dynamic service line items, live public-preview iframe, send workflow, error-surfaced save states.
Proposal Settings (Defaults)
Route: /settings/proposals (inside SettingsLayout)
Icon slot: reuses sidebar_proposals for consistent admin-customizable icon mapping.
Profiles defaults added: default cover image, validity days, immediate availability, payment structure, payment methods, installment description, and conditions notes.
Create Proposal modal preloads these defaults into newly created proposal records.
